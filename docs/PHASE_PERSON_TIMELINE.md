# Phase C — صفحة الشخص الكاملة + Timeline

آخر تحديث: 2026-08-27

الحالة: **منفذة في الكود مع Unit/UI tests؛ تنتظر إغلاق بوابة CI الكاملة للرأس الحالي مع بقية Post-MVP features.**

## الهدف

تجميع علاقة المستخدم مع الشخص في شاشة واحدة دون دمج حسابات أو عملات مختلفة حسابيًا. الصفحة تعرض بيانات الشخص، حساباته، ملخصات منفصلة حسب العملة والاتجاه، وسجلًا زمنيًا موحدًا للأحداث المرتبطة بحساباته.

## التنفيذ الحالي

تم تنفيذ:

- `PersonTimelineActivity`.
- `PersonTimelineScreen`.
- `PersonTimelineViewModel`.
- `PersonTimelineNavigation`.
- `PersonTimelineBuilderTest`.
- `PersonTimelineUiInstrumentedTest`.
- فتح الحسابات الأخرى من صفحة الشخص.
- Multi-currency note ومنع netting بين العملات/الاتجاهات.
- Font Scale 2.0 regression في UI test.

## مبادئ ثابتة

- الشخص هو التجميع الأعلى، لكن كل دين/حساب يبقى Ledger مستقلًا.
- لا يوجد صافي واحد بين عملات مختلفة.
- لا تدمج أرصدة «له» و«عليه» في رقم مضلل.
- Timeline للعرض ولا يغير السجل المالي.
- الأحداث مشتقة من البيانات الدائمة؛ لا جدول Timeline مالي مكرر بلا حاجة.
- فتح أي حساب يعيد استخدام شاشة Account Details ومصدر الحقيقة نفسه.

## النطاق المنفذ

### رأس صفحة الشخص

- الاسم.
- بيانات الاتصال والملاحظات عند توفرها.
- معلومات الحسابات المتاحة للشخص.

### الملخص

- تجميع مستقل لكل `(currency, direction)`.
- الحفاظ على كل عملة واتجاه منفصلين.

### قائمة الحسابات

تعرض الحساب والاتجاه والعملة والأصل/المتبقي والوصف وما يلزم لفتح الحساب.

### Timeline

يبني عناصر عرض من البيانات المتاحة المرتبطة بحسابات الشخص دون إعادة كتابة Ledger. الترتيب واختيارات الأحداث مغطاة بمنطق builder واختباراته.

## الاختبارات

### Unit

- تجميع الأرصدة حسب العملة والاتجاه.
- منع netting المضلل.
- Timeline ordering/building.

### UI

- شخص بعدة حسابات/عملات.
- فتح حساب آخر من الصفحة.
- بقاء الرأس والحسابات والTimeline قابلة للوصول مع Font Scale 2.0.

## ما تبقى قبل إغلاق Phase C

1. مرور Android instrumentation الكامل على الرأس النهائي.
2. Accessibility audit أوسع: TalkBack/focus/touch targets.
3. التأكد من ظهور أحداث Claims/Attachments/Documents الجديدة بالشكل المقصود عندما تكون موجودة في الـTimeline contract النهائي.
4. تحديث Evidence في `CHANGELOG.md` و`HANDOFF.md` بعد CI الأخضر.

لا تحتاج Phase C Migration مستقلة؛ الصفحة Projection/Read model فوق البيانات الحالية.
