# وثائق تنفيذ وَصل

آخر تحديث: 2026-08-27

## مصادر الحالة

- `CURRENT_STATUS.md` — الحالة الحية والمراحل المتبقية وترتيب العمل.
- `../HANDOFF.md` — نقطة التسليم الهندسية للرأس الحالي والخطوة التالية.
- `../PROJECT_CONTEXT.md` — صورة المنتج والبنية والثوابت.
- `DATABASE_SCHEMA.md` — Room Schema v9 وMigrations وBackup contract.
- `TEST_PLAN.md` — بوابات الجودة والاختبارات الحالية.
- `ARCHITECTURE.md` — الطبقات واتجاه الاعتماد ومصادر الحقيقة.
- `NAVIGATION.md` — المسارات الحالية والتكيف وDeep links.

## وثائق المراحل

- `PHASE_CLAIMS.md` — «طالبني» / Payment Claims: منفذة وظيفيًا وتنتظر إغلاق CI الكامل.
- `PHASE_ATTACHMENTS.md` — خزنة المرفقات: منفذة وظيفيًا وتنتظر إغلاق CI الكامل.
- `PHASE_PERSON_TIMELINE.md` — تصميم/تاريخ صفحة الشخص؛ التنفيذ الحالي موجود في الكود ويجب قراءة `CURRENT_STATUS.md` للحالة الأحدث.
- `PAYMENT_CLAIMS.md` — تفاصيل إضافية لسلوك المطالبات عند الحاجة.

## المراجع العليا

- `../WASL_MASTER_PROJECT_PROMPT.md` — المرجع التأسيسي الأعلى للمنتج.
- `../SPEC.md` — المواصفات التشغيلية ومعايير القبول.
- `../DECISIONS.md` — القرارات المعمارية طويلة المدى.
- `../CHANGELOG.md` — سجل التغييرات والتحقق.
- `../AGENTS.md` — قواعد العمل الإلزامية للمطور/الوكيل.

## قاعدة التعارض

إذا تعارضت وثيقة قديمة مع التنفيذ الحالي فلا نخمن ولا نعيد بناء ميزة موجودة. ترتيب التحقق هو:

1. الكود الحالي على الفرع النشط.
2. Room exported schema وMigrations.
3. CI evidence للرأس نفسه.
4. `CURRENT_STATUS.md` و`HANDOFF.md` المحدثان.
5. الوثائق التاريخية/المرحلية.

يجب تحديث الوثيقة القديمة بدل ترك تعارض صامت.
