# Phase C — صفحة الشخص الكاملة + Timeline

## الهدف

تجميع علاقة المستخدم مع الشخص في شاشة واحدة دون دمج حسابات أو عملات مختلفة حسابيًا. الصفحة تعرض بيانات الشخص، كل حساباته، ملخصات منفصلة حسب العملة والاتجاه، وسجلًا زمنيًا موحدًا للأحداث التي تخص حساباته.

## مبادئ ثابتة

- الشخص هو التجميع الأعلى، لكن كل دين/حساب يبقى Ledger مستقلًا.
- لا يوجد صافي واحد بين عملات مختلفة.
- لا تُدمج أرصدة «له» و«عليه» في رقم مضلل؛ تعرض حسب الاتجاه والعملة.
- Timeline للعرض فقط ولا يغير السجل المالي.
- الأحداث مشتقة من البيانات الدائمة الموجودة أصلًا؛ لا نكرر بيانات مالية في جدول جديد بلا حاجة.
- فتح أي حساب من صفحة الشخص يعيد المستخدم إلى شاشة الحساب الحالية نفسها.

## النطاق الوظيفي

### 1. رأس صفحة الشخص

- الاسم.
- الهاتف والبريد والملاحظات عند توفرها.
- عدد الحسابات النشطة/المؤرشفة المتاحة للشخص بحسب البيانات التي يستطيع المستودع إرجاعها.

### 2. ملخص الحسابات

- تجميع مستقل لكل `(currency, direction)`.
- أصل المبالغ، المسدد، والمتبقي لكل مجموعة.
- منع جمع YER مع SAR أو USD.
- منع طرح «عليه» من «له» تلقائيًا.

### 3. قائمة الحسابات

لكل حساب:
- الاتجاه.
- العملة.
- أصل الدين.
- المتبقي.
- تاريخ الفتح والاستحقاق إن وجد.
- وصف مختصر.
- زر فتح الحساب.

### 4. Timeline موحد

ترتيب تنازلي حسب الوقت، مع tie-breaker ثابت. الأحداث المرشحة:
- فتح الحساب.
- تسجيل دفعة.
- عكس دفعة.
- وعد سداد وإنهاؤه.
- مطالبة سداد وإنهاؤها.
- إصدار مستند.
- إضافة مرفق.

كل عنصر يوضح الحساب/العملة والحدث دون تغيير المعنى المحاسبي.

### 5. التنقل

- مدخل واضح من تفاصيل الحساب إلى «صفحة الشخص».
- رجوع يحافظ على سياق الحساب الذي جاء منه المستخدم.
- فتح حساب آخر للشخص من الصفحة ينتقل إلى تفاصيل ذلك الحساب.

## التصميم التقني المفضل

ابدأ دون Migration جديدة ما دام كل شيء مشتقًا من الجداول الحالية:

- `PersonTimelineViewModel` يجمع تدفقات البيانات الحالية.
- استخدام `WaslRepository.observeAccounts()` ثم التصفية حسب `person.id` ما لم تضف واجهة استعلام أدق دون كسر التوافق.
- `PaymentPromiseStore` و`PaymentClaimStore` و`AttachmentStore` تُجمع لكل debtId.
- المستندات والحركات المالية تؤخذ من `AccountOverview`/`DebtLedger`.
- لا تخزن Timeline كسجلات مكررة.

## حالات الواجهة

- Loading.
- Person/account not found.
- شخص بحساب واحد.
- شخص بعدة حسابات وبعملة واحدة.
- شخص بعدة عملات واتجاهات.
- Timeline فارغ/جزئي.
- خطأ تحميل فرعي لا يمنع عرض باقي البيانات إن أمكن.

## الاختبارات المطلوبة

### Unit

- تجميع الأرصدة حسب العملة والاتجاه.
- عدم netting بين العملات أو الاتجاهات.
- ترتيب Timeline وتحديد tie-breaker.
- تحويل Payment/Reverse/Promise/Claim/Document/Attachment إلى عناصر العرض الصحيحة.

### Instrumentation / UI

- فتح صفحة الشخص من الحساب.
- ظهور حسابين أو أكثر لنفس الشخص.
- فتح حساب آخر من الصفحة.
- ظهور Timeline بترتيب صحيح.
- حالة multi-currency واضحة.
- RTL وعدم قص النص الأساسي على شاشة هاتف عادية.

### Regression

- الحساب الحالي وتسجيل الدفعات والعكس والاستحقاق والمستندات والمرفقات تظل تعمل.
- lint + unit + instrumentation + debug build + CI كلها خضراء.

## بوابة الإغلاق

لا تعتبر Phase C مكتملة إلا عند:

1. نجاح الاختبارات الجديدة والقديمة.
2. CI أخضر بالكامل.
3. عدم إضافة Migration بلا حاجة.
4. تحديث `docs/CURRENT_STATUS.md` و`HANDOFF.md` و`CHANGELOG.md`.
5. توثيق أي قرار معماري جديد في `DECISIONS.md` إذا لزم.
